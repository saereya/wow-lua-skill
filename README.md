## Layout

- `signatures.txt`: one line per function, method, event, enum and structure. Grep this first.
- `api/systems/<System>.md`: functions, events and types of each API system (`C_*` namespaces and globals).
- `api/widgets/<Widget>.md`: methods of each widget type (Frame, Texture, FontString ...).
- `api/events.md`: every event with its payload. `api/enums.md`: every `Enum.*` table and constant.
- `framexml/templates.md`, `framexml/mixins.md`, `framexml/functions.md`: what Blizzard's own UI code
  defines that addons can inherit from, mix in or call. Each entry gives its source path and line.
- `SKILL.md`: instructions that let AI agents use this folder as a skill (see below).
- `luals/`: `---@meta` annotation files for the Lua language server (VS Code "Lua" by sumneko/LuaLS).
- `api.json`: the full parsed documentation, field for field, plus the FrameXML index.

## Notation

- `C_Foo.Bar(a: number, b: string?) -> x: number, y: string?`: a `?` after a type means it may be `nil`.
- `T[]` is an array-like table of `T`. Named types (structures, enums, callbacks) are defined in the
  same system file or another one; grep `signatures.txt` for `struct <Name>` or `enum <Name>`.
- Enum values are accessed as `Enum.<Name>.<Value>`.
- Flags such as `SecretArguments=AllowedWhenUntainted`, `SecretReturns`, `HasRestrictions` or
  `RequiresX` come straight from Blizzard's documentation. Functions marked `IsProtectedFunction` can
  only run from secure code, which usually means outside combat and from a hardware event. "Secret"
  values (for example `SecretWhenInCombat`) are opaque to tainted addon code: they can be passed back to
  the API or displayed, but not compared or used in arithmetic.

## Writing an addon for this build

An addon is a folder in `Interface/AddOns/<Name>/` containing `<Name>.toc` and the files it lists:

```
## Interface: <toc version>
## Title: My Addon
## Notes: What it does
## SavedVariables: MyAddonDB
MyAddon.lua
```

Blizzard's own TOC files do not carry a version number, so get the right `## Interface:` value in game
with `/dump select(4, GetBuildInfo())`. A minimal event handler:

```lua
local f = CreateFrame("Frame")
f:RegisterEvent("PLAYER_LOGIN")
f:SetScript("OnEvent", function(self, event, ...)
  print("Hello from", event)
end)
```

## Use as an Agent Skill

`SKILL.md` makes this folder a skill. For Claude Code, unzip the download into `~/.claude/skills/`, or
into `.claude/skills/` inside an addon repository. The folder name has to stay `wow-addon-api-wowf`.
Regenerating after a game patch replaces it in place.

## Notes for AI agents

- Treat these files as the authority for this build. They override memory of other WoW versions:
  functions are often moved into `C_` namespaces or renamed between expansions.
- To check that a function exists, search `signatures.txt` for its name, then open the system file
  for argument details. Do not call functions you cannot find here or in `framexml/`.
- Prefer `C_` namespace functions and events listed here over deprecated globals.
- When a return is a structure, look up `struct <Name>` to learn its fields.
- `framexml/*` entries are Lua and XML that Blizzard's UI defines. They exist only once that UI code has
  loaded; templates can be used in `CreateFrame(type, name, parent, "TemplateName")`.
